# Character Lens

アニメ・漫画・ゲームのキャラクター候補と、特徴別の推定類似度を調べるWindows向けアプリです。
PythonからOllamaを操作します。接続先は自分で登録したOllamaのIPアドレスで、画像はその接続先へ送信されます。

## 起動

軽量な移行用ZIPでは、大容量モデルを移行先のPCで取得します。詳しくは「移行手順.md」を参照してください。推奨環境はPython 3.14.6（64bit）です。

1. Ollamaを起動します。
2. このフォルダーの **app.py** をPythonで実行します。
3. 初回準備画面で不足するライブラリと専用モデルを取得します。Ollamaの接続やモデル確認はアプリ画面で行います。必要なら同梱履歴を復元してから「アプリを開始」を押します。
4. 本体の「接続・モデル確認」で接続済みと表示されることを確認します。

コマンドから起動する場合は、このフォルダーで `python app.py` を実行します。
仮想環境やバッチファイルは使用しません。別のPCで追加ライブラリが必要な場合は、初回準備画面の「ライブラリを導入」を使います。手動の場合は使用するPythonで `python -m pip install --user -r requirements-migration.txt` を実行してください。Tkinterが付属するPythonを使ってください。

## 基本操作

1. 「画像を追加」または「フォルダーを追加」を押します。サブフォルダーを含める場合はチェックを付けます。
2. 画像モデルを選択します。初期候補は `qwen3-vl:latest` です。モデル名にlatestが含まれる場合も、解析時の実際のモデル識別子を履歴に記録します。
3. 通常は「専用モデルで候補を絞る」を有効にします。
4. 「全画像を開始・再開」または「選択した画像を解析」を押します。
5. 左の画像を選ぶと、中央に画像、右に候補・特徴別の点数・理由が表示されます。

「全画像」は絞り込みに関係なく一覧へ登録した全画像です。対象を限定したい場合は、画像を選択して「選択した画像を解析」を使います。CtrlキーやShiftキーで複数選択できます。

### 専用モデルとOllamaの役割

初回準備で取得するWD ViT Tagger v3が、学習済みのキャラクタータグから候補を検索します。分類出力が0.85以上の候補を最大3件採用します。この値は暫定基準で、正答確率や外見の類似度ではありません。

Ollamaは最初に名前を伏せて外見を観察し、その後で専用モデルの候補について特徴別に評価します。専用モデルのタグは変更しません。日本語名・作品名は `character_names.json` に登録した名前を使用します。初版の辞書はμ'sの9名と東雲絵名の10件です。辞書未登録の場合は元のタグを名前として表示し、作品名はモデルの推定として扱います。辞書は表記の補助で、画像識別の正解を与えるものではありません。識別できるタグ全体をこの10件に制限しません。

名前辞書は文字情報だけで、公式画像は含みません。出典URLは記録用で、解析時にはアクセスしません。辞書を編集した場合は新しい解析条件として扱い、以前のキャッシュを流用しません。

専用モデルで候補が得られない場合も、2段階目のOllama評価は最後まで実行します。このとき候補は制限せず、専用モデルの候補なしという記録と注意点を結果に残します。対応するキャラクターが未登録、衣装や画風が大きく異なる、顔が小さい等の場合には見逃しがあります。「候補なし」はオリジナルキャラクターの証明ではありません。

専用モデルのチェックを外すと、Ollamaの知識だけによる自由探索になります。実機の試行では存在しない名前や誤った作品名も出たため、候補の発見補助として使用し、人が確認してください。

### 指定キャラクターを評価

モードを「指定キャラクターを評価」にし、右の欄に名前と、必要なら作品名を入力します。名前を伏せた観察の後、指定したキャラクターについて評価します。専用モデルの判定は参考として別に残します。名前を指定したこと自体は一致の根拠ではありません。

### 点数の意味

公式画像を収集・照合する機能ではありません。点数は、モデルが学習したキャラクター像に対する暫定の特徴評価です。公式画像との実測一致率・正答確率・制作元の証明ではありません。

| 特徴 | 集計上の重み |
|---|---:|
| 髪 | 20 |
| 顔・目 | 20 |
| 衣装 | 15 |
| 固有の目印 | 30 |
| 配色 | 5 |
| 体形・種族的特徴 | 10 |

各軸の点数はOllamaの推定です。画面上の6本の重みでPythonが平均し、小数を四捨五入します。重みはアプリのフォルダーの`setting.json`に保存されます。見えない・比較対象の知識が不確かな軸はnull（評価不能）とし、平均の分母から除きます。評価できた重みが設定した重み合計の半分未満の場合、総合点は表示しません。

例: 髪80点と固有の目印90点だけ評価できた場合、評価範囲は50%、総合点は86点です。50%の範囲だけを根拠にした点であり、画像全体を評価できたわけではありません。重み・採用基準はいずれも未校正です。

「確かさ」はモデルの自己申告です。数値の高低だけで判断せず、理由と画像を確認してください。見ていない公式画像を比較したような説明や、不正なJSONは検査で拒否します。ただし、すべての事実誤りを自動検出するものではありません。

実画像の検証では、Ollamaが画像内の衣装をキャラクター固有の目印と取り違え、高い点数を付けた例もあります。初版は候補と特徴を調べる補助ツールであり、点数の精度・正解率は未検証です。人による正解データと比較して校正する機能は含みません。

### 範囲指定

画像を選び「範囲を指定」を押し、顔・人物などをドラッグして囲みます。その後「選択した画像を解析」を押します。元画像は変更しません。「全体に戻す」で解除できます。

複数人がいる場合は、対象人物の範囲を手動で指定してください。初版に人物の自動検出・自動分割はありません。過去の結果は以前の範囲に対する結果として残ります。

### 中断・再開と履歴

- 「中断」で新しい処理を止め、進行中のOllama接続を切断します。画面は中断を受け付け続けます。Ollama側の処理終了には少し時間がかかる場合があります。
- 1枚ごとの完了結果と、第1段階の観察をSQLiteへ保存します。再起動しても残ります。
- 同じ画像内容・範囲・モデルの実体・プロンプト・評価条件で完了済みなら再利用します。
- 第2段階で中断・失敗した場合、第1段階の観察から再開できます。
- 「完了済みも再解析」を有効にすると、新しい履歴を追加します。以前の結果は保持します。
- モデルやプロンプトを変更して比較したいときは、変更後に再解析し「過去の解析」タブで切り替えます。
- 元画像が解析中に変わった場合、その結果は採用しません。解析後の変更もプレビューで通知し、HTMLでは変更された画像の添付を省略します。

### 人による確認と書き出し

修正名・メモ・確認済みを保存できます。AIの元結果は書き換えません。保存した修正だけでモデルが再学習されることはありません。

「結果を書き出す」から、絞り込み中の全画像をHTML、CSV、JSONで保存できます。HTMLは小さい画像を埋め込んだ単一ファイルです。CSVはExcelで開きやすいUTF-8 BOM付きです。JSONには解析条件と詳細を含みます。画像の元パスが含まれるため、他者へ渡す際は内容を確認してください。

「一覧から外す」は一覧表示だけを外します。元画像・履歴は削除しません。同じ画像を追加すると再表示できます。

## 保存場所と移行

軽量な移行用ZIPには、コード・説明書・テスト・モデル検証情報と、25枚分の画像一覧および26件の解析履歴を収録しています。履歴は初回準備画面から任意に復元できます。元画像と大容量モデルは含みません。元画像は別途コピーし、初回準備画面でコピー先のフォルダーを指定してください。

- `data/character_lens.sqlite3`: 画像一覧、解析結果、設定、確認メモ。
- `data/errors.log`: 画面処理で例外が起きた場合の記録。
- `models/wd-vit-tagger-v3/`: 取得した専用モデル、同梱のタグ一覧、出典、ライセンス。
- `migration/`: 移行元の履歴と検証情報。AI結果、元パス、設定を含みます。
- `migration_profile.json`: 移行元のPython・ライブラリ・Ollamaモデルの版。
- `prompts/` と `schemas/`: プロンプトと出力形式。解析履歴にも使用時の内容を保存します。

本体の履歴や専用モデルはアプリのフォルダー内に保存します。ライブラリ導入は実行中のPythonのユーザー領域、OllamaモデルはOllamaの保存先に書き込みます。元画像は読み取りだけです。

履歴はメニューの「履歴データをバックアップ」で保存できます。復元する場合はアプリを終了し、現在のdataフォルダーを別名で保管してから、バックアップを新しいdataフォルダーのcharacter_lens.sqlite3として配置してください。実行中のSQLiteファイルを直接コピーしないでください。

## 接続・失敗時

- 接続先はHTTPのIPアドレスまたはlocalhostです。通常は `http://127.0.0.1:11434` を使い、別PCは例として `http://192.168.1.20:11434` を「新規」で登録します。登録した接続先と重みはアプリのフォルダーの`setting.json`に保存されます。
- 「応答が止まった場合の上限秒」は、ストリームの受信ごとに延長されます。遅くても受信が続く間は最終回答まで待機し、「中断」はいつでも使えます。
- 画像対応のローカルモデルだけを表示し、クラウドモデルは選択対象にしません。解析時に外部API、Web検索、画像アップロードは行いません。
- モデルがない場合は「初回準備・移行」で取得ボタンを押してください。取得時だけインターネットを使用します。既存のOllamaモデルは上書きしません。
- 重いモデルでタイムアウトする場合は、待ち時間を600/900秒にするか、小さいモデルを選んでください。
- JSONの形式不一致は1回だけ再試行し、2回とも不正なら失敗として理由を残します。
- 一部のQwen環境ではJSONがthinking欄に入ります。通常回答が空で、代替欄の全文が有効なJSONの場合のみ採用します。推論文からJSON断片を抜き出すことはありません。
- PNG/JPEG/WebP/BMP/GIF/TIFFに対応します。アニメーション・複数ページ画像は先頭フレームだけです。EXIF回転を反映し、透過部を白で合成、指定の長辺へ縮小した画像をモデルへ渡します。EXIF・ファイル名は渡しません。
- 100MB超または5000万画素超の画像は、小さいコピーを用意してください。

## 検証と初版の範囲

2026年9月6日・画像表示の修正: 説明欄の高さを固定し、画像を読み込むたびに表示領域が変わる循環を解消しました。同じ画像・範囲・表示サイズの再読み込みを省略し、新しい画像の準備が完了するまで現在の画像を保持します。

自動テストは `python -m unittest discover -s tests -v` で実行できます。ローカルの模擬HTTPサーバーを含み、画像の外部送信はありません。

実装済み: ローカルOllama、WD候補絞り込み、自由/指定判定、6軸評価、手動範囲指定、一括処理、中断再開、履歴、確認メモ、絞り込み、HTML/CSV/JSON、バックアップ。

未実装: 人物の自動検出、公式画像との比較、複数Ollamaモデルの自動同時比較、モデルの追加学習、文字辞書編集画面、画像生成、法的な判断。複数モデルの比較は、モデルを切り替えて履歴で確認できます。
